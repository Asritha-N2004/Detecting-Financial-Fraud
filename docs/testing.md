# Verification

Backend: `python -m pytest -q` from backend. Numerical tests use hand-computed ratios and independent NumPy references for return losses, sample volatility, quantiles, expected shortfall and drawdown. Validation tests cover missing/invalid denominators, applicability, invalid weights, inconsistent balances, mixed currencies, nonfinite prices and unsorted dates. Agent tests verify actual tamper detection and correction, source limitations, bounded loops, and explicit failure coverage loss. API tests use a disposable SQLite database, exercise the full persisted lifecycle and stress test, deny cross-organization access, verify upload validation and role restrictions, and confirm repeated execution is rejected. Database sessions are disposed before Windows temporary-directory cleanup.

Frontend: `pnpm test` checks unavailable scores, warning/failure statuses, accessible errors, empty-state navigation and manual JSON validation before API requests. `pnpm build` runs strict TypeScript checking and creates the production bundle. Playwright's lifecycle test creates a workspace, starts a synthetic assessment, inspects all evidence pages and executes a stress scenario against the actual API. Start the API before the E2E command. Chromium must be installed in the execution environment.

Specialist/provider tests now exercise all five role prompts, dimension-specific source packets, strict schema and SDK HTTP contracts, bounded read-only function dispatch, unauthorized tools and arguments, fabricated references, model refusal, timeouts, source/instruction separation, unchanged numeric outputs and saved token totals. The actual OpenAI SDK is exercised against `httpx.MockTransport`, with no external request or paid credential. UI tests verify unverified-interpretation disclosures and deterministic fallback.

Durable job tests exercise concurrent claims, lease renewal/expiry, stale-worker fencing on every write type, runtime mismatch, bounded attempts, shutdown requeue, queued work across API restart, all six checkpoint boundaries including reflection, and finalization from a `done` checkpoint. One test kills a child process with `os._exit(73)` immediately after committing a checkpoint, then recovers in a fresh process whose specialist executor rejects any repeated completed analysis. Exactly one final explanation and completion audit event are asserted.

Evaluation: `python -m app.evaluation` executes 24 controlled ablation cases and records observed results. This is a software-reliability experiment, not a calibrated financial performance study.

Engine v2 tests independently form centered covariance matrices and weighted return series; check annualization, risk-contribution sums and negative hedging contributions; handle singular and constant-price inputs; reject mixed currency/origin, duplicate symbols, inconsistent weights and invalid dates; verify each maturity bucket boundary and bounded operating-flow coverage; and reconcile accounting projections, amortizing floating interest, receipt delays, capex/dividends/restricted cash and intraperiod funding gaps. API assertions verify real constituent persistence, stress artifacts and tenant isolation. UI/browser checks cover matrix/maturity views, complete evidence-bundle staging and positive closing cash with an earlier shortfall. See [detailed methodology](portfolio_maturity_stress.md).

Dependency installation and local sockets require expanded permissions in the Windows execution sandbox. Do not replace financial logic to work around a blocked event-loop socket. The local host currently has newer preinstalled Python dependencies than some declared compatibility ranges; a fresh locked environment and PostgreSQL/container tests remain important reproducibility work.

CI defines Linux backend migration/tests/evaluation, frontend build/component/integration tests, and a separate browser job with a SQLite-backed local API and Chromium. The new browser job definition has not been executed in GitHub Actions here; local equivalents are verified separately. Docker/PostgreSQL CI remains outstanding.

The frontend integration suite uses a test-only Axios adapter at the HTTP boundary while retaining actual Axios serialization/auth interceptors, React Query cache/mutations/polling, routing and rendered pages. Its 23 tests cover login rejection/success, bearer headers, organization-switch cache clearing, pagination, error/empty data, demo invalidation, create→run ordering, run failure, multipart staging, validation errors, durable-job polling/recovery, 401/404, failed/incomplete assessment results, reflection/explanation/audit views, exploratory weights, synthetic history disclosures, stress errors and assessment switching. Recharts is retained; only browser-only responsive measurement is replaced by fixed dimensions in these tests. Real browser tests verify layout/curves and backend behavior.

Synthetic response fixtures are generated from the Python engine using `python scripts/export_frontend_fixtures.py`; `python scripts/export_sensitivity_demo.py` regenerates the clearly labeled history demonstration. No production user data or API credentials are included. Component tests and HTTP-adapter integration tests do not replace the real backend browser suite or representative financial model validation.

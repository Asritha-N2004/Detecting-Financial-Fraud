# Research scope and responsible use

The system is financial decision support, not autonomous investment advice, an established credit rating, a fraud determination, or a guaranteed prediction. Scores and thresholds are explicitly illustrative; confidence labels describe available evidence and are not probabilistic confidence. Missing source dimensions and unverified provenance remain visible.

Implemented controls include tenant-scoped API reads, role checks, scrypt hashing, expiring signed JWTs, CORS allowlists, parameterized ORM operations, validated schemas, compressed upload and expanded XLSX size checks, request logging without secrets, and a local process rate limiter. The current limiter is not distributed; chunked requests and HTTP body handling need hardened perimeter limits. Session tokens are stored in browser session storage and are vulnerable if the application suffers XSS. Refresh-token rotation, MFA, invite flows, user/role management UI and account recovery are not implemented.

Operational assessments only score supplied indicators; they do not infer actual fraud incidents, regulatory violations or control effectiveness. User text is untrusted. Specialized LLM roles now use configurable administrator-owned prompts, strict schemas and a bounded read-only metric lookup tool. Runtime dispatch rejects unauthorized tools and references; generated interpretations remain separately labeled unverified. These controls do not establish semantic truth or complete prompt-injection resistance. The default deterministic mode avoids paid-provider dependency entirely. Live model/provider validation remains outstanding.

Financial ratio scoring overlaps correlated dimensions and is not calibrated to industry or jurisdiction. Stock denominators use ending balances. Constituent sample covariance, risk contributions and dated maturity/cash gaps are now implemented, with strict calendar/currency/source validation; optimization, dynamic correlations, FX conversion, derivative exposure and liquidity-adjusted liquidation costs remain outside scope. Historical market tails require much more data for reliable estimation. Maturity cash coverage is bounded to 365 days and cannot establish adequacy from incomplete flows. Stress projections depend on explicit tax-shield realization, fixed/variable costs, cash conversion and noncash-asset assumptions; they do not guarantee funding or future performance. Infeasible or unfunded projections withhold scores. Conditional aggregate changes hold historical market and operational risk fixed.

Critic checks share quantitative code with analysts and cannot independently validate its formulas. Reflection repairs detectable software inconsistencies; it cannot produce new external evidence or certify document authenticity. Normal synthetic scenarios may run zero correction cycles. Real-world accuracy or financial return improvement has not been measured.

Overlap/input-reuse diagnostics, explicit weight sensitivity and optional score-history covariance are implemented. They do not establish a calibrated redundancy correction: shared fields need not imply redundant economic risks, different fields can still be economically dependent, and historical score-level correlation is not loss dependence or causality. At least 30 complete comparable observations are required, but this alone does not establish statistical reliability. Real-world validation and time-series uncertainty estimation remain outstanding. Saved assessment scores are never automatically discounted.

Durable leased jobs and application-managed graph stage resume are now implemented and crash-tested on SQLite. In-flight stages may replay; model billing and total token usage are not exactly-once. The five specialists currently share one checkpoint boundary, and the queue is not a substitute for verified PostgreSQL load/failover testing. Distributed caching, execution streaming, database row-level security, immutable audit storage, retention/deletion workflows, production dependency locks, calibrated PD serving, SHAP for a deployed model, representative research datasets, comprehensive frontend tests and production load/security testing remain work. Redis, Statsmodels and QuantStats were not added because no implemented feature required them.
